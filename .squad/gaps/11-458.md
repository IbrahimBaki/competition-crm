# Story 458 Implementation Gaps

## Pre-existing Test Suite Failures

**Status**: Non-blocking observation

The full `php artisan test` suite has ~115 pre-existing test failures in unrelated domains (Security, Attachment, CollectionQuery, BotProtection, etc.). These failures existed before Story 458 implementation and are unrelated to the customer functionality.

**Impact**: Customer-specific code and tests work correctly. The seeder tests were updated to include new permissions and now pass. The ApiConventionsAuditTest also has a pre-existing issue (call to undefined `basePath()` method).

**Recommendation**: Address existing test failures in a separate story or cleanup pass. Story 458's customer implementation is complete and functional.

## Type Hints Warnings (phpstan)

Several phpstan warnings about missing type hints on return types and iterable value types in:
- FormRequest `rules()` return types
- Service method return types

**Impact**: Non-critical warnings. Code is functionally correct; type hints would improve static analysis only.

**Recommendation**: Add return type declarations if desired: `public function rules(): array<string, string>` pattern.

## API Conventions Audit Test Issue

The `ApiConventionsAuditTest` itself has a pre-existing bug (tries to call `base_path()` during test setup and fails on Container::basePath() call).

**Impact**: Test cannot verify customer controllers. However, customer controllers now properly use `CollectionQuery` for pagination in `index()` methods (CustomerContact, CustomerNote, CustomerAttachment), so they comply with the no-unpaginated-lists rule.

**Recommendation**: Fix test infrastructure separately. Manual verification confirms customer index methods use proper pagination.
