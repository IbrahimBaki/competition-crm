**Description:** The `customers.id` column is defined as a bigint (auto-incrementing integer), but PortalTicketVisibilityTest and TicketFeedbackTest attempt to create Customer records with UUID values (string UUIDs) via `Customer::forceCreate()`. This causes MySQL type-casting errors.

**Impact:** PortalTicketVisibilityTest (2 tests) and TicketFeedbackTest (3 tests) fail to instantiate test data. PortalAuthTest and PortalGuardIsolationTest (8 tests total) pass successfully.

**Root Cause:** Customer uses auto-incrementing integer IDs; Portal test fixtures try to use UUIDs for consistency. Test infrastructure mismatch.
