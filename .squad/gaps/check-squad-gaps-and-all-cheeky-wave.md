# Close all .squad/gaps + fix migration crash — full backlog

## Context

`.squad/gaps/` contains 17 free-form status reports written by prior implementation sessions for stories 453–478. The user asked to review all of them, close every remaining gap (full backlog, not a subset), fix the `php artisan migrate` crash on `2026_08_28_040300_add_reporting_indexes.php`, and produce a resolved/unresolved ledger. Design work below was authored by Opus 5 per the user's request.

Two research passes happened before designing:
1. Read all 17 gap files — they describe SLA (464), Automation (465), Agent Tasks/Watchers/Mentions (467), WhatsApp/SMS (470), Chat (471), Feedback (472), Customer Portal (474), AI Assistance (473), Reporting (475), Integrations (476), OpenAPI contract (477), and a frontend schema bug (478) as incomplete to varying degrees.
2. Verified **current** code against those claims (git log shows heavy activity since most gap docs were written). Result: **several gap docs are stale** — already fixed and should NOT be re-touched:
   - department_id FK type mismatch (470/471/472) — already fixed at the source in commit `eaf0613`. Three now-redundant "fix" migrations remain as harmless dead weight.
   - Customer UUID-vs-bigint id mismatch (474) — already fixed in the two Portal test files.
   - Log redaction of tokens (476) — already implemented and tested, contrary to the gap doc.
   - Bulk import CSV reading/validation (476) — already implemented (gap doc said "not implemented").
   - Most of OpenAPI story 477's Tasks 4–8 — already on disk.
   - Story 478's "missing `items` key" — already fixed; what remains is schema *quality*, not breakage.

   Meanwhile, deep-reading the actual current code (not just old status docs) surfaced a second layer of **currently-live bugs that no gap doc mentions**, several severe:
   - `app/Providers/AppServiceProvider.php` is missing `use` imports for the entire Automation class tree → every `TicketAutomationHooks`-related binding resolves to a nonexistent class today (verified via tinker).
   - `TicketResource::computeSlaBlock()` references 4 unimported classes → **every ticket API response currently fatals**.
   - `PostTicketMessage` references unimported AI classes and has a closure `use()`-capture bug → AI-suggestion approval silently never persists.
   - `ResolveAiSuggestion` calls `AuditLogger::log()`, which doesn't exist (real method is `record()`) → the AI human-approval critical path fatals on every accept/discard.
   - `AiSuggestion`/`AiUsageRecord`/`Customer` models are missing the standard `uuid` `creating`-hook other UUID models have → inserts fail at the DB (NOT NULL, no default). `Customer` additionally has this masked by `$fillable` silently dropping `uuid`/`name_normalised` on every `create()` call — **production `CreateCustomer` is currently broken**, not just tests.
   - `ApiTokenController` calls `$this->authorize()` without `extends Controller`/`AuthorizesRequests` → fatals on every call.
   - `ReportScheduleSweepCommand` calls `$locked->toExport()`, which doesn't exist, and its inline `computeNextRun()` ignores `day_of_week`/`day_of_month` entirely.
   - `ReportExportController` was built but never registered in `routes/api.php`.
   - `PerformanceDatasetSeeder` does raw `DB::table()->insert()` against columns that don't exist / omits NOT NULL columns → cannot run.
   - The reporting-indexes migration's `down()` calls a nonexistent `dropIndexIfExists()`, mirroring the `up()` crash.
   - `RunImport` resolves an attachment path via a nonexistent `disk_path` attribute → import validation fails before reaching the (also fake) import pass.

This plan fixes all of it: the reported migration crash, every confirmed-current gap from the 9 incomplete stories, and every newly-discovered live bug encountered along the way (since several block the very tests that would verify the gap fixes). Stale/already-resolved items are explicitly called out as **no action** so they aren't redone.

Layering conventions to follow throughout (per `CLAUDE.md` / skills): business logic in Action classes, validation in FormRequests, authorization in Policies via permission keys (`module.action.scope`, never role-name comparison), output shape in Resources, thin Controllers. Bilingual admin fields use `{ar, en}` via `BilingualStringCast`. Sensitive mutations get an `AuditLogger::record()` entry. Duration/SLA math goes through `WorkingTimeService`, never raw `diffInMinutes()`. All IDs UUID at the API boundary; models needing this get `getRouteKeyName() → 'uuid'` plus a `booted() { static::creating(...) }` hook if they lack one, matching `User`/`ChatSession`'s existing pattern.
