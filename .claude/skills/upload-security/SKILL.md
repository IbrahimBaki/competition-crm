# أساسيات الأمان — رفع الملفات والمدخلات العامة (مبني على BE-09)

## المدخلات بشكل عام
- كل input يتحقق منه server-side بقواعد صريحة (Form Request / Validator)، مفيش ثقة في أي شيء جاي من العميل.
- Mass assignment مقفول افتراضيًا (`$fillable` صريح، مش `$guarded = []`).
- الأسرار (مفاتيح API، بيانات اعتماد) تعيش في `.env`/config فقط، أبدًا في الكود، وأبدًا مرجوعة في أي endpoint.

## رفع الملفات
- حد أقصى للحجم + allowlist لأنواع الملفات (مش blocklist).
- تُخزَّن **خارج الـ web root**، بمعرّفات غير قابلة للتخمين (UUID مش اسم الملف الأصلي).
- **الفحص من الفيروسات إلزامي**: ملف تحت الفحص = حالة "quarantined" مميزة، وفشل الفحص = كود خطأ مميز (مش رفض عام).
- الوصول لأي مرفق يتحقق منه في كل طلب — معرفة الـ ID لوحده **لا يكفي أبدًا** لجلب الملف.

## Endpoints عامة (بدون تسجيل دخول)
زي: نموذج الويب، ودجت الشات، روابط الاستبيان، تتبع الضيف
- Rate limiting إلزامي.
- حماية من البوتات (captcha أو ما يعادلها).
- لا يرجع أي بيانات داخلية حتى لو الـ identifier اتخمّن بالصدفة.

## نقاط تحقق
- [ ] هل الملف اتخزن بمعرّف غير قابل للتخمين وخارج web root؟
- [ ] هل فيه حالة "قيد الفحص" منفصلة عن "مقبول"/"مرفوض"؟
- [ ] هل الـ endpoint العام ده محمي بـ rate limit؟
- [ ] هل تجربت تجيب مرفق بمعرف عشوائي/لعميل تاني وتتأكد إنه بيترفض؟
