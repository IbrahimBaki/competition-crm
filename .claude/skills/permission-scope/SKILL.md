# الصلاحيات والنطاق (مبني على BE-03)

## القاعدة الذهبية
**ممنوع نهائيًا** أي كود يقارن اسم الدور مباشرة، زي:
```php
if ($user->role->name === 'admin') { ... } // ❌ خطأ جسيم
```
بدل كده، كل تحقق لازم يمر على **مفتاح صلاحية ثابت** بالصيغة:
```
{module}.{action}[.{scope}]
```
مثال: `tickets.update.own`, `customers.view.department`, `reports.export.any`

## النطاقات (scopes) المتاحة
`own` → `team` → `department` → `any`

النطاق مش بس على الفعل (action)، لازم يتفرض على الاستعلام نفسه (query-level)، مش فلترة بعد الجلب:
```php
// ✅ صح: النطاق جزء من الـ query
Ticket::query()->scopeFor($user, 'tickets.view')->paginate();

// ❌ خطأ: تجيب كل حاجة وتفلتر بعدين (leak محتمل + أداء سيء)
Ticket::all()->filter(fn($t) => $t->department_id === $user->department_id);
```

## نقاط تحقق إلزامية
- [ ] هل التحقق بيتم عن طريق Policy مربوطة بمفتاح صلاحية، مش `if ($user->can(...))` عشوائي بدون تعريف مسبق للمفتاح في الكتالوج؟
- [ ] هل الأدمن (role الإداري) محمي من حذف صلاحياته الإدارية الأساسية؟
- [ ] هل `GET /auth/me` بيرجع **مفاتيح الصلاحيات** مش اسم الدور؟ (الفرونت يبني الواجهة على المفاتيح فقط)
- [ ] هل فيه static check/test بيتأكد إن مفيش role name string اتقارن في أي مكان بالكود؟
