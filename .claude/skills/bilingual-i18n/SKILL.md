# ثنائية اللغة كخاصية معمارية (مبني على BE-06)

## القاعدة
العربي والإنجليزي **جزء من شكل البيانات نفسها**، مش ترجمة بتضاف في الآخر.

## عند تخزين أي حقل بيكتبه الأدمن (اسم فرع، اسم حالة، فئة، ...)
```php
// ✅ يتخزن كـ object فيه اللغتين
'name' => ['ar' => 'فرع القاهرة', 'en' => 'Cairo Branch']

// ❌ ممنوع: عمود واحد بس
'name' => 'Cairo Branch'
```
ويترجع كـ object فيه اللغتين مع كل response، مش لغة واحدة مختارة مسبقًا — عشان الفرونت يقدر يبدّل اللغة من غير طلب تاني.

## أي نص بيتقال للمستخدم من السيرفر (رسالة خطأ، إشعار، إيميل)
- **ممنوع** أي string حرفي في الكود: `return response()->json(['message' => 'Not found'])` ❌
- **الصح**: يعدّي على ملفات ترجمة: `__('errors.not_found')` ✅
- استثناء واحد: السيرفر ما يرجعش نصوص "chrome" (زرار/عنوان واجهة) — دي مسؤولية الفرونت.

## قواعد إضافية
- Fallback موثّق: لو حقل بلغة فاضي، يتحدد بوضوح إيه اللي يترجع بدله (مش سلوك عشوائي).
- تحديد اللغة (locale resolution) بالترتيب: `Accept-Language` → إعداد المستخدم → إعداد المؤسسة الافتراضي.
- تخزين واسترجاع UTF8MB4 صحيح للعربي في كل مكان: القاعدة، البحث، التصدير (Excel/PDF)، الإيميل.

## نقاط تحقق
- [ ] هل الحقل الجديد ده بيتخزن `ar`+`en` معًا؟
- [ ] هل فيه أي نص إنجليزي/عربي مكتوب مباشر في كود الباك-إند بدل ملف ترجمة؟
- [ ] لو الحقل بيظهر في تقرير PDF، هل العربي بيتصدّر باتجاه RTL صحيح؟
